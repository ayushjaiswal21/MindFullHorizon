# Deploy for zero rupees (Render + Neon + GitHub)

Owner goal (2026-11-24): the deployment must cost nothing, no card, no billing. This guide is the zero-cost variant of [DEPLOY.md](DEPLOY.md) (read that for the general background). It is honest about what free cannot do. Facts about vendor limits were checked on 2026-11-24 from public pages and can change: re-read each vendor page before relying on a number.

## What you get and what you do not

| Part | Free service | Limit that matters |
|------|--------------|--------------------|
| Web app | Render free web service (Docker) | Sleeps after 15 minutes without requests (cold start about a minute); 750 instance hours a month (a 31 day month needs 744); filesystem is erased on every restart |
| Database | Neon free Postgres | About 1 GB storage per project; compute sleeps after 5 idle minutes; 100 compute hours a month (the app is built so that Neon can sleep) |
| Keep awake and outage alarm | GitHub Actions cron (free because the repository is public) | Scheduled runs can start 5 to 30 minutes late; Render's terms on keep-alive traffic are not clear (see "Risks") |
| Domain | `https://<name>.onrender.com` | No custom domain |
| AI | Gemini free key, general content only | Personal text is never sent (`AI_SEND_PERSONAL_TEXT=0`, owner decision): Google may use content sent through free keys to improve its products |
| Email | None for now (owner decision) | No reminder emails and no escalation emails; dashboard alerts only |
| Audio | The free GitHub Pages site `mindfull-audio` (step 6) | Soft limits: 1 GB site, 100 GB a month |

**Free cannot give you:** a guarantee that the server is always on, SMS or phone paging, email, long backup history, a custom domain. Because crisis escalation timers run inside the web process, a sleeping or restarting instance delays them. Use free for a demo and for a small supervised pilot with a named on-call counsellor (see [review/PILOT_PLAN.md](review/PILOT_PLAN.md)), and move the web service to a paid always-on instance before a larger launch. The product never promises 24x7 monitoring and always shows Tele-MANAS 14416, KIRAN 1800-599-0019 and 112.

## Before you start

1. Revoke every key that was ever committed (old Gemini keys, CloseRouter, OpenRouter): see docs/MEMORY.md, "History rewrite". Create new secrets only in the host dashboards, never in git.
2. Use your own GitHub account for Render and Neon sign-in. None of the steps below needs a card (neither vendor's pages asked for one; confirm on screen and stop if a card is requested).

## Step 1: Neon (database)

1. neon.com, Sign up (GitHub login). Create a project: name `mindfull`, Postgres 16 or newer, the region closest to your users (Singapore, or Mumbai if offered).
2. Open Connection details. Copy the **direct** connection string (host without `-pooler`) and keep it private. It already ends with `sslmode=require`.
3. In the project settings keep "Scale to zero" on (it cannot be turned off on the free plan).

## Step 2: Render (web app)

1. render.com, Sign up with GitHub. New, Blueprint, pick the repository `ayushjaiswal21/MindFullHorizon`, branch `main`. Render reads `render.yaml` (Docker web service, free plan, health check `/health`).
2. Fill the environment variables when asked (values that are not secrets are already in `render.yaml`):
   - `DATABASE_URL`: the Neon direct string from step 1.
   - `SITE_URL`: `https://<your-service-name>.onrender.com` (the final name is shown on the service page; edit it after the first deploy if it differs).
   - `SECRET_KEY`, `PROVIDER_INVITE_CODE`, `DOCTOR_INVITE_CODE`: generated by Render; copy the two invite codes somewhere safe.
   - `GEMINI_API_KEY`: the rotated key (optional: used only for the daily tip and general content).
   - `AI_SEND_PERSONAL_TEXT`: leave `0`.
   - `ENABLE_PRESCRIPTIONS`: `1` (owner decision; only verified doctors can issue).
   - `GRIEVANCE_EMAIL`, `DATA_FIDUCIARY_NAME`: the legal contact and the college name from the signed agreement (the privacy page shows placeholders until set).
   - Leave the SMTP variables and `CRISIS_ESCALATION_EMAIL` empty (no email in the zero-cost setup).
3. Create. The first build takes several minutes. Open the Logs tab until you see the app listening, then open `https://<name>.onrender.com/health` (expect `{"status":"ok"}`) and `/ready` (expect `ready`).
4. Run `python scripts/predeploy_check.py` on your own computer with the same variables exported to see warnings before real users arrive.

## Step 3: first admin (Render free has no shell)

Run this on your own computer, pointed at the Neon direct URL (the command prompts for a hidden password; details in [ADMIN_SETUP.md](ADMIN_SETUP.md)):

```powershell
$env:DATABASE_URL = "<neon direct url>"
$env:FLASK_APP = "app.py"
flask create-admin --email you@example.com --name "Your Name" --institution "Your College" --pharmacy-desk
```

Sign in at `https://<name>.onrender.com/admin/login`. Doctors sign up with `DOCTOR_INVITE_CODE`, counsellors with `PROVIDER_INVITE_CODE`; the admin verifies each doctor under Admin, Doctor verification.

## Step 4: keep-alive and outage alarm (GitHub)

1. Repository Settings, Secrets and variables, Actions, tab Variables, New repository variable: name `SITE_URL`, value `https://<name>.onrender.com`.
2. The workflows `Keep-alive` (every 5 minutes, requests `/health`) and `Post-deploy check` (after each green CI run) start working. `/health` does not touch the database, so Neon keeps sleeping.
3. Settings, Notifications (your profile), Actions: turn on email for failed workflows. A failed `Keep-alive` run means the site did not answer after three tries: that is your free outage alarm.
4. GitHub disables scheduled workflows after 60 days without repository activity; any commit re-enables them.

## Step 5: deploy only after CI passes

In the Render service, Settings, Build and Deploy, Auto-Deploy: "After CI checks pass" (or the `autoDeployTrigger: checksPass` field in `render.yaml` if the Blueprint sync accepts it; see [CICD.md](CICD.md)). Rollback: Render, Events, pick an earlier successful deploy, Rollback.

## Step 6: audio files (free, already set up)

The 16 real tracks of the MIT-licensed Binaural Beats Dataset (Neel Kamath) are published at `https://ayushjaiswal21.github.io/mindfull-audio/` from the public repository `ayushjaiswal21/mindfull-audio` (GitHub Pages, created on 2026-11-24; `tracks/`, `data.json`, `tracks.csv`, `LICENSE`). `render.yaml` already sets `AUDIO_BASE_URL` to that address. The app redirects `/audio/tracks/<file>.mp3` there for files it does not have locally, and the content security policy allows that origin as `media-src`. Check one track plays on the Music page after the first deploy.

The 30 files that used to sit in the app's `audio/` folder were 44-byte placeholders with no sound; they were not uploaded. If the music page offers a mood match that points at `audio/`, it needs the real tracks instead (open item in TRACKER).

## Weekly routine (10 minutes)

- Neon, Billing/Usage: storage under 1 GB and compute hours under 100 (an idle app should use a few hours a month).
- Render, Metrics: restarts, memory (the app uses about 150 MB of the free 512 MB).
- GitHub, Actions: look for red `Keep-alive` runs.
- Admin, Overview: pending doctor verifications, low stock, open crisis follow-ups.
- Backups: run `python scripts/backup_db.py <folder outside the repo>` from your computer (Neon free keeps only a short restore window; confirm it on the Neon pricing page).

## Risks you accept with the zero-cost setup

| Risk | Why | What reduces it |
|------|-----|-----------------|
| Render objects to keep-alive traffic | A Render community post calls keeping a free service awake abuse; the terms were not read | If Render ever blocks it, remove the workflow: the app still works with cold starts. Upgrade the service when the pilot grows |
| Late escalation | Cron can run late; Render can restart at any time; the worker restarts and recovers overdue jobs on start | Named on-call counsellor with a phone SOP, counsellors check the dashboard, students always see helplines |
| Neon limits | 1 GB and 100 compute hours | Event-driven worker, DB-free `/health`, small pilot cohort |
| Free Gemini terms | Content sent through a free key may be used by Google | Personal text is never sent; keep `AI_SEND_PERSONAL_TEXT=0` unless the college approves in writing |
| Public repository | Anyone can read the code | No secrets in git (history was rewritten on 2026-11-24 and keys revoked); keep `.env` untracked |

## When to leave zero-cost

Move the Render service to a paid always-on instance (about 7 US dollars a month at the time of writing; price not verified) when real students depend on timely alerts, when you need email, or when the pilot passes a few dozen active users.
